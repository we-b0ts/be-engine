# Migration Use Of E2E Run State

Treat `recorded-e2e-cases` and the `traffic-e2e` runner as the sole authorities
for run-state schemas, lifecycle, counters, aggregation, progress, recovery, and
verified excludes. This reference defines only how migration work consumes and
delivers that state.

## Stable Project Inputs

Keep these source-controlled target inputs under `.traffic-e2e/`:

- `e2e.yaml`, generated and validated by `traffic-e2e init`;
- `replay.yaml`, owned by the recorded replay contract;
- `recorder.toml`, when managed recorder feedback is configured;
- `e2e-progress.yaml`, generated by the runner as concise human progress.

Confirm `project_cli`, `replay_policy`, and `pr_base` before initialization.
Configure `recorder_config` and `recording_rule` together or omit both. Do not
hand-write `e2e.yaml`, copy its schema from this reference, or repair a rejected
configuration manually. Use the installed CLI and the `recorded-e2e-cases`
runner workflow as the current contract.

## Local Evidence Boundary

The target root `.gitignore` MUST contain:

```gitignore
.traffic-e2e/local/
```

Verify a representative local path with `git check-ignore` before runner state
is created. The runner owns every file under `.traffic-e2e/local/`, including
current pointers, run indexes, active attempts, focused and full-round
snapshots, reports, logs, sessions, and temporary files.

AI MUST NOT create, edit, merge, repair, copy, stage, commit, or force-add those
files. Read their exact paths and identifiers from runner output when diagnosis
or handoff requires them. Never infer a run key, copy a focused result into a
full-round result, or manufacture a terminal state.

## Progress And Completion

`e2e-progress.yaml` is runner-generated and Git-eligible. Commit it whenever the
runner changes it for a delivered migration increment, including an
`incomplete` or `blocked` increment. AI may inspect and deliver it but MUST NOT
edit, merge, reconstruct, or validate its counters. Treat its current
logical-run status as a human summary; use the full `recorded-e2e-cases`
completion gate and runner-owned local evidence for canonical completion.

Focused attempts update only their selected API contribution. They never become
global full-round evidence through file operations. Follow
`recorded-e2e-cases` to decide whether grouped focused evidence is sufficient
or a full round is required, and use runner commands for interrupted-state
recovery or abort.

## Delivery Check

Before commit:

1. Require `git check-ignore` to confirm the local evidence boundary.
2. Require `git ls-files .traffic-e2e/local` to return no tracked local
   evidence.
3. Inspect the staged diff and exclude every `.traffic-e2e/local/` path.
4. Include a changed runner-generated `e2e-progress.yaml` for every delivered
   migration increment, including `incomplete` or `blocked`.

Ignoring local evidence does not waive a missing canonical artifact or permit a
completion claim.
